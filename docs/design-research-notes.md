# 外部设计守则审计笔记

## taste-skill

来源：https://github.com/Leonxlnx/taste-skill

- 目标是避免 AI 生成千篇一律、低辨识度的界面，强调框架无关、设计意图优先。
- 使用设计拨盘控制视觉结果，重点维度包括设计变化度（variance）、动效强度（motion）和信息密度（density）。
- 反模板化规则要求避免默认居中布局、装饰性元素堆叠、无意义的胶囊与版本标签、过量分割线，以及缺乏内容层级的卡片堆叠。
- 近期版本强调先完成设计系统地图，再执行重设计，并对暗色/亮色模式、色彩/形状/主题一致性、CTA 对齐、垂直节奏、动效和文案进行检查。

## impeccable

来源：https://github.com/pbakaus/impeccable

- 重点是让 AI 在现有产品上执行有纪律的设计审计和渐进式重构，而不是单纯换颜色。
- 设计检查应覆盖版式、颜色、间距、交互、动效、内容层级、组件、图标、代码质量，以及暗色/亮色模式的一致性。
- 重构优先级应先处理高影响问题：信息架构与层级、布局与间距、字体与可读性、颜色对比度、交互状态，再做最后视觉润色。
- 需要验证完整状态：加载、空状态、错误、成功、禁用、长文本、窄屏和深浅色主题，而不是只检查静态主视图。

## 对 ZedScope 的应用结论

ZedScope 是 Android 原生壳 + WebView + Go 内核，不应照搬 Web CSS；应将原则转化为 Material 3/XML/Kotlin 设计系统：统一 token、可复用 surface/card/button/list 状态、明确导航层级、稳定 8dp 间距节奏、至少 44dp 触控目标，并覆盖浏览器、抓包、Token、AI、代理、会话、设置等完整状态。现有 DESIGN.md 已经有冷蓝黑背景、单一青色强调、玻璃面和无发光/无渐变纪律，后续应在不破坏功能资源 ID 的前提下系统化落实，并把未实现功能和状态补齐。
